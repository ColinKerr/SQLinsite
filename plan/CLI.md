# CLI

The CLI tool is call `sqlinsite`.

## Commands

- `sqlinsite profile` - Profiles a SQLite file using a set of queries specified in an input file.  See details in [PROFILE.md](./commands/PROFILE.md)
  - `--db-file` - SQLite file to test.  Statements run **in place**; write statements permanently modify this file.
  - `--statements` - A file with one or more SQLite statements to use in the profiling test.  Uses [Statements File Format](./commands/PROFILE.md#statements-file-format).
  - `--out-file` - Path to save the output SQLite db (raw page-access log + run metadata).  Uses [Output File Format](./commands/PROFILE.md#output-file-format).
  - `--timing` - `raw` (default) emits raw monotonic-clock ticks; `relative` rebases `timeStart`/`timeEnd` to the start of the run so they begin near zero. `timeEnd - timeStart` is the per-access cost either way.
  - `--quiet` - Suppress the run summary printed to stderr.
- `sqlinsite map` - Maps the schema tables, data tables, and indexes to  the pages storing them.  Output for each page includes header information, free bytes, rows/keys it holds, and pointers to other pages.  The result is written as a SQLite db for performance that scales to billions of rows.  See details in [MAP.md](./commands/MAP.md)
  - `--db-file` - SQLite file to map.
  - `--out-file` - Path to save the generated map (a SQLite database).
- `sqlinsite visualize` - Command to visualize `sqlinsite profile` and `sqlinsite map` results.  See details in [VISUALIZE.md](./commands/VISUALIZE.md)
  - `sqlinsite visualize serve` - Start a local web server hosting an interactive canvas view (runs in the foreground; Ctrl-C to stop).
    - `--map-file` - Path to map file generated by `sqlinsite map` command.
    - `--profile-file` - Optional.  Path to the profile SQLite db generated by `sqlinsite profile`; imported as loaded ('input') sources of the unified profile overlay. Interactive Query-view runs are added as ('query') sources of the same overlay, so any profile can be shown in any view.
    - `--db-file` - Optional.  The SQLite database mapped by `--map-file`; opened read-only. Enables the live **Query** view (run SQL and see the pages it touches). See [VISUALIZE_LIVE_QUERY_VIEW.md](./commands/QUERY_VIEW.md), and is the no-prefix base of the **Analysis** Query Metrics (see [ANALYSIS_VIEW.md](./commands/VISUALIZE/ANALYSIS_VIEW.md)).
    - `--manifest-file` - Optional.  Path to the Cloud Backed SQLite `manifest.bcv` for the container.  Enables the **Block** view (page→block mapping) and the block metrics of the **Analysis** view.  See [BLOCK_VIEW.md](./commands/VISUALIZE/BLOCK_VIEW.md).
    - `--manifest-db-name` - Optional.  Which named database in the manifest the `--map-file` corresponds to.  Defaults to the newest (highest-id) non-deleted database whose block count matches the mapped file; a mismatch disables the Block view with a warning.
    - `--port` - Optional.  Listen port (default `8080`; `0` picks a free port).
- `sqlinsite --help` (or `-h`) - Print usage and exit.

Options accept both `--flag value` and `--flag=value` forms. Unknown commands,
unknown options, and missing option values are reported with usage and exit code 2.


## Error policy

If a statement fails to prepare or step, the error is reported to stderr and
profiling **continues** with the next statement (one bad statement does not
abort the session). The overall process exit code is non-zero if any statement
failed. Rows already emitted for successful statements are kept.

Exit codes: `0` success, `1` a runtime failure occurred (bad statement, missing
test file, output error), `2` invalid command line.
